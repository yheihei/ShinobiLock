# 利用案内の削除とルール操作の広告確認

2026年9月13日。以下の仕様で実装。

選んだアプリから離れることを目的とし、ホームで利用を勧める案内を削除する。本人が選ぶ広告による5分解除と、解除中の残り時間表示は維持する。

## 操作ごとの仕様

| 操作 | 動作 |
| --- | --- |
| ホームの「少しだけ使いますか？」カード | 「5分だけ使う」ボタンとともに削除 |
| 広告による5分解除 | 維持。カルマの間、残り時間表示、期限後の再ロックを含む |
| 個別ルールの削除 | 確認画面、カルマの間、広告視聴を経てから削除 |
| 有効なルールの休止 | 確認画面、カルマの間、広告視聴を経てから休止 |
| すべてのルールを休止 | 機能を削除。個別の休止を使用 |
| 曜日・時間帯・対象アプリ・名前の編集 | これまでどおり広告なしで保存 |
| ルールの再開・新規作成 | 広告なし |

削除は休止中のルールも対象。休止はホームのスイッチと編集画面の「有効」をオフにして保存する操作の両方に適用する。ロック時間外でも個別の削除・休止には広告を挟む。

編集によって制限が弱まる場合も、今回は広告を挟まない。ただし、「有効」をオフにする変更は休止として扱う。

## 削除・休止の流れ

1. 操作するルールの名前と、削除・休止の結果を確認する。
2. 「広告を見て削除する」「広告を見て休止する」を選ぶと、カルマの間を表示する。
3. 「やめておく」で元のルールを維持する。「それでも広告を見て…する」で広告へ進む。
4. 広告の報酬が確定したら、指定したルールの操作だけを実行する。
5. 広告が閉じた後、ホームまたは編集元の画面に戻る。

削除は元に戻せず、休止は再び有効にするまで続く。5分後に元に戻る操作ではない。

広告の中断、読み込み失敗、圏外、広告の在庫切れでは、ルールを変更しない。再試行できる。編集中に休止を選んだ場合、ほかの編集内容も広告完了まで保存せず、休止と同時に保存する。

広告表示中に対象のルールが変更・削除された場合は、その広告の結果で操作を実行しない。報酬の重複通知や、終了した広告からの古い通知も操作を繰り返さない。

## カルマの台詞

[karma-lines.json](../App/Resources/karma-lines.json)に操作別の台詞を保存する。

- `unlock_before_ad`: 5分解除の前。
- `pause_before_ad`: ルール休止の前。
- `delete_before_ad`: ルール削除の前。
- `stayed`: 5分解除をやめたとき。
- `rule_stayed`: ルールの削除・休止をやめたとき。

## 今回変更しないもの

この変更時点では解除画面の既存の文言と、解除をやめた後の再表示条件を対象外としていた。その後の[利用の勧誘をなくす方針](unlock-intent.md)で、この2点も修正対象とした。広告SDK、広告のプライバシー設定、曜日・時間帯ルール、カルマの素材を維持する。

## 検証

- Swift Packageのテストで台詞の切り替え、旧形式の台詞ファイルの読み込み、報酬の重複・古い通知、5分の期限と週間ルールを検証。
- `python3 scripts/check_rule_actions.py --simulator <UDID>`で、実際の保存・変更処理に対する14件の確認を実行する。iOSの監視・ロックAPIは代替実装を使うため、実機でのロック動作を保証するものではない。
- シミュレータの確認記録は[広告付きルール操作の検証](rule-action-verification.md)を参照。
