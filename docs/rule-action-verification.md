# 広告付きルール操作の検証

2026年9月13日。iOS 26.5のシミュレータで確認。

## 確認した動作

| ケース | 結果 |
| --- | --- |
| 設定画面 | 一括休止がなく、広告のプライバシー表示・設定は残る |
| ホームの個別スイッチをオフ | 直ちに休止せず、対象ルールと広告条件の確認画面へ進む |
| 休止前のカルマの間 | 休止用の台詞と「それでも広告を見て休止する」を表示 |
| カルマの間で中止 | ホームに戻り、保存済みの全ルールが有効なまま残る |
| 休止の公式テスト広告を完了 | 選んだ1件だけが休止し、ホームに戻る |
| 編集画面から削除 | 削除の確認画面と削除用のカルマの間へ進む |
| 削除の公式テスト広告を完了 | 選んだ1件だけが消え、編集画面も閉じてホームに戻る |
| 曜日を減らして保存 | 広告を表示せず保存。ルールは有効のまま |
| 編集画面で「有効」をオフにして保存 | 即保存せず、休止の広告確認画面へ進む |
| 編集画面からの休止を中止 | 保存済みのルールは有効のまま |
| 広告IDを空にして表示失敗を発生させる | エラーと再試行の入口を表示。保存済みのルールは変わらない |

公式テスト広告では画面の「Test mode」を確認した。広告のリンク先への移動や購入は行っていない。

## 検証用アプリの範囲

検証用Bundle IDは `com.example.shinobilock.ruleactionsqa`。本体のルールとは別の合成データを使用した。画面、広告SDK、保存トランザクション、ルール変更処理は実装を使用し、Screen Timeの許可・監視・ロックAPIのみ代替実装に差し替えた。

操作前後のJSONを読み、対象以外のルールが維持されることを確認した。広告失敗テストの後は、検証用アプリの広告IDを公式テストIDに戻した。

## 自動確認

Swift Packageの23テストが成功。カルマの台詞・素材、報酬通知の扱い、5分の期限、週間ルールの既存テストを含む。

`python3 scripts/check_rule_actions.py --simulator <UDID>`で14件が成功。広告なしの直接休止の拒否、キャンセル後の状態維持、対象ルールだけの休止・削除、他アプリのロック維持、重複報酬の拒否、古いルールに対する操作の拒否、広告なしの通常編集、5分解除の期限を検証した。

実行ログは `build/rule-action-check.log`。Swift Packageのテストは `build/rule-action-ads-tests-final.log`、アプリのビルドは `build/rule-action-ads-build-final.log`。
