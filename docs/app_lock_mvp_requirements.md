# アプリロックアプリ MVP 要件定義書

- 文書バージョン: 1.1
- 作成日: 2026-09-09
- 更新日: 2026-09-10
- 対象: iPhone向け初期版（MVP）
- アプリ名: 未定
- 参考UI: ユーザー提供のOpal画面

## 1. 概要

指定した曜日・時間帯に、指定したアプリを利用できない状態にするiPhoneアプリを開発する。

ロック中に対象アプリを押すとロック画面を表示し、その押下を1回として記録する。どうしても利用したい場合は、リワード広告を最後まで視聴すると、そのアプリだけを5分間利用できる。

## 2. 目的

- SNSやゲームなどを無意識に開く行動を減らす。
- ロック中に対象アプリを押した回数を可視化し、利用者が自分の行動に気づけるようにする。
- 完全禁止にはせず、必要時には広告視聴というひと手間を経て短時間だけ利用可能にする。

## 3. MVPの基本方針

- 機能は「時間帯ルール」「アプリのロック」「押下回数」「広告による5分間の一時解除」に限定する。
- アカウント登録やサーバーを使用せず、設定と記録は端末内に保存する。
- 保護者による強制管理ではなく、本人の自発的な利用制限を目的とする。
- Opalの画面構成は参考にするが、名称・文章・デザインは独自のものとする。

## 4. 用語

| 用語 | 定義 |
| --- | --- |
| ルール | 対象曜日、開始時刻、終了時刻、対象アプリをまとめたロック設定 |
| ロック時間 | 有効なルールの曜日・時間帯に該当している期間 |
| 対象アプリ押下 | ロック時間中に、利用者が対象アプリを開こうとしてOSのロック画面が表示される操作 |
| 押下回数 | 対象アプリ押下を記録した回数 |
| 一時解除 | 広告視聴完了後、対象アプリのロックを5分間だけ解除すること |

## 5. 対象範囲

### 5.1 MVPに含める機能

1. スクリーンタイム制御の利用許可
2. 時間帯ルールの作成・編集・削除・有効化・無効化
3. 対象アプリの選択
4. 指定曜日・時間帯での自動ロックと自動解除
5. OSのShieldを利用したロック画面
6. ロック中の対象アプリ押下回数の記録
7. 今日の押下回数の表示
8. リワード広告視聴による5分間の一時解除

### 5.2 MVPに含めない機能

- 1日の使用時間上限によるロック
- Webサイトやアプリカテゴリ単位のロック
- ハードモード、解除禁止モード、長押し確定
- ポモドーロタイマー、集中セッション
- 友達、ランキング、バッジ、連続達成記録
- AIによる分析や助言
- アカウント登録、ログイン
- クラウド同期、複数端末同期
- 通知機能
- 押下後に閉じたか、広告を見たか、解除に成功したかの行動分析
- Android、iPad、Macへの対応

## 6. 機能要件

### FR-01 初回利用許可

- 初回起動時に、アプリの制限に必要な利用許可を利用者へ求める。
- 許可の用途を事前に日本語で説明する。
- 許可されていない場合はルールを有効化できない。
- 許可が取り消された場合は、その状態と再設定方法を表示する。

### FR-02 ルール一覧

- 登録済みルールを一覧表示する。
- 各ルールに以下を表示する。
  - ルール名
  - 対象曜日
  - 開始時刻と終了時刻
  - 対象アプリ数
  - 有効／無効
- 新規作成、編集、削除、有効化、無効化ができる。
- 複数のルールを登録できる。

### FR-03 ルール設定

ルールには以下を設定できる。

| 項目 | 必須 | MVP仕様 |
| --- | --- | --- |
| ルール名 | 必須 | 1〜30文字 |
| 開始時刻 | 必須 | 1分単位で指定 |
| 終了時刻 | 必須 | 1分単位で指定 |
| 曜日 | 必須 | 日〜土から1日以上選択 |
| 対象アプリ | 必須 | インストール済みアプリから1個以上選択 |
| 有効／無効 | 必須 | 保存時は有効を初期値とする |

- 初版では、開始時刻より終了時刻が後になる同日内の時間帯だけを登録可能とする。
- 日付をまたぐ設定は対象外とする。必要な場合は複数ルールに分ける。
- 同じアプリを複数ルールの対象にできる。

### FR-04 自動ロック

- 有効なルールの開始時刻になったら、対象アプリを自動的にロックする。
- 終了時刻になったら、対象アプリのロックを自動的に解除する。
- ロック中のホーム画面上の表示は、iOSが提供する制限表示に従う。
- アプリ側でホーム画面アイコンの色や見た目を保証しない。
- ルールを無効化または削除した場合、該当ルールによるロックを解除する。

### FR-05 複数ルールの重複

- 同じアプリに対して複数ルールが有効な場合、いずれか1つでもロック時間中ならロックする。
- 1つのルールが終了しても、別の有効ルールが継続中ならロックを継続する。

### FR-06 ロック画面

ロック中の対象アプリを押した場合、対象アプリの代わりにOSのShieldを利用したロック画面を表示する。

表示内容は以下を基本とする。

- 本アプリのロゴまたは名称
- タイトル: 「このアプリはロックされています」
- 対象アプリ名を含むロック案内
- 当該アプリの今日の押下回数: 「今日 N回」
- ボタン1: 「閉じる」
- ボタン2: 「広告を見て5分使う」

- 「閉じる」を押した場合はロックを解除せず、ロック画面を閉じる。
- 「広告を見て5分使う」を押した場合は、対象アプリを直接開かず、本アプリの広告・解除画面を開く。
- 本アプリへ移動しただけではロックを解除しない。
- 説明文は短くし、長い宣伝文や累計実績はMVPでは表示しない。

Shieldの表示項目やレイアウトにはiOS側の制約があるため、最終的な見た目はOS仕様の範囲内とする。

### FR-07 押下回数の記録

- ロック時間中に対象アプリを押した時点で、押下回数を1増やす。
- 同じ対象アプリを再度押した場合は、その都度1増やす。
- ロック時間外の押下は記録しない。
- 一時解除中の押下は記録しない。
- 「閉じる」の押下、広告の開始・中断・完了、一時解除の成否では回数を増やさない。
- 日付の判定には端末の現地時刻を使い、日付が変わると「今日」の表示を0から集計する。
- 端末再起動や本アプリの終了後も当日の回数を保持する。

### FR-08 回数表示

- アプリのホーム画面に、全対象アプリを合算した今日の押下回数を表示する。
- アプリ別の今日の押下回数を一覧表示する。
- ロック画面には、対象アプリ名と当該アプリの今日の回数を「今日 N回」の形式で表示する。
- ホーム画面では「今日、このアプリを開こうとした回数: N回」のように、何を数えているか誤解のない文言にする。
- MVPでは過去日付のグラフや詳細履歴は表示しない。

### FR-09 広告による一時解除

1. 利用者がロック画面の「広告を見て5分使う」を押す。
2. 対象アプリはロックしたまま本アプリを開き、対象アプリ名と「広告視聴後に5分間だけ利用可能になる」ことを表示する。
3. 利用者が明示的に広告視聴を開始する。
4. リワード広告を最後まで視聴し、広告SDKの報酬獲得イベントを受け取る。
5. 押下した対象アプリだけを5分間解除する。
6. 利用者は自分で対象アプリへ戻る。
7. 5分経過時点でルールのロック時間中なら、対象アプリを再ロックする。

- 同じルールに含まれる他のアプリは解除しない。
- 広告を途中で閉じた場合は解除しない。
- 広告の取得または表示に失敗した場合は解除せず、「広告を表示できませんでした。時間をおいて再度お試しください」と表示する。
- MVPでは広告視聴回数、解除要求回数、解除成功回数を利用者向けに記録・表示しない。
- 広告視聴は利用者が選択する方式とし、自動再生しない。

### FR-10 一時解除中の扱い

- 一時解除の残り時間を本アプリに表示する。
- 本アプリが終了しても解除終了時刻を保持する。
- 端末時刻の変更だけで解除時間を延長できないよう、可能な範囲で単調時刻または保存済み期限との整合を確認する。
- ルールの終了時刻が一時解除の終了時刻より早い場合は、ルール終了を優先する。

## 7. 画面要件

| 画面 | 主な内容 |
| --- | --- |
| 初回説明・許可画面 | 機能説明、必要な利用許可の要求 |
| ホーム画面 | 今日の合計押下回数、アプリ別回数、登録ルール一覧への導線 |
| ルール一覧画面 | ルール一覧、新規作成、有効／無効、編集、削除 |
| ルール作成・編集画面 | 名前、開始、終了、曜日、対象アプリ、保存 |
| アプリ選択画面 | iOS標準の選択UIによる対象アプリ選択 |
| ロック画面 | ロック案内、今日の回数、閉じる、広告付き一時解除 |
| 広告・解除画面 | 解除対象、5分間の説明、広告再生、エラー、解除残り時間 |

## 8. データ要件

### 8.1 ルール

| 項目 | 内容 |
| --- | --- |
| ID | ルールを識別する端末内ID |
| 名前 | ルール名 |
| 開始時刻／終了時刻 | 毎日のロック時間 |
| 曜日 | 選択された曜日 |
| 対象アプリ | iOSが提供するアプリ識別トークン |
| 有効フラグ | 有効／無効 |
| 作成日時／更新日時 | 管理用日時 |

### 8.2 押下記録

| 項目 | 内容 |
| --- | --- |
| 対象アプリ | iOSが提供するアプリ識別トークン |
| 押下日時 | ロック中に対象アプリが押された日時 |

### 8.3 一時解除状態

| 項目 | 内容 |
| --- | --- |
| 対象アプリ | 一時解除対象 |
| 解除終了日時 | 5分間の解除が終わる日時 |

- データは端末内にのみ保存する。
- アプリの選択情報や押下記録を、広告配信や行動ターゲティングのために送信しない。
- アプリ削除時はデータも削除される。

## 9. 非機能要件

| 分類 | 要件 |
| --- | --- |
| 対応端末 | iPhoneのみ |
| 対応OS | 技術検証後に確定。Shieldから本アプリを開けるOSバージョンを下限候補とする |
| オフライン | ルール設定、ロック、回数記録はオフラインで動作する。広告表示には通信が必要 |
| 性能 | ルール開始・終了後、OSの許容範囲内で速やかに状態を反映する |
| 信頼性 | アプリ終了・端末再起動後もルールと当日の回数を維持する |
| プライバシー | 必要最小限の権限と端末内データだけを利用する |
| アクセシビリティ | Dynamic Type、VoiceOver、十分なコントラストに対応する |
| 言語 | 初版は日本語のみ |

## 10. 受入条件

### AC-01 ルールによるロック

- 指定曜日の開始時刻になると、選択したアプリがロックされる。
- 未選択のアプリはロックされない。
- 終了時刻になるとロックが解除される。

### AC-02 押下回数

- ロック中に対象アプリを1回押すと、当該アプリの今日の回数が1増える。
- 同じ条件で3回押すと3回になる。
- ロック時間外および一時解除中に押しても増えない。
- ロック画面の各ボタンや広告操作では増えない。

### AC-03 一時解除

- 広告の報酬獲得イベントを受け取るまで対象アプリは解除されない。
- 広告視聴完了後、押下したアプリだけが5分間利用可能になる。
- 5分後もルール時間中なら再度ロックされる。
- 広告を中断した場合や表示できない場合は解除されない。

### AC-04 永続化

- 本アプリを終了・再起動してもルールと当日の回数が失われない。
- 日付が変わると「今日」の表示は新しい日だけを対象に集計される。

## 11. 実装前に必須の技術検証

以下はMVPの要件だが、公開APIだけで想定どおり実現できるかを実機試作で確認する。

| 優先度 | 検証項目 | 合格条件 |
| --- | --- | --- |
| P0 | ロック中の対象アプリ押下検知 | 対象アプリを押すたびに、ボタン操作なしで1回ずつ記録できる |
| P0 | Shieldから本アプリへの遷移 | 一時解除を選ぶと本アプリを開き、解除対象を引き継げる |
| P0 | 5分後の再ロック | 本アプリがバックグラウンド・終了状態でも、5分後に再ロックできる |
| P0 | Family Controls entitlement | 本体と必要な拡張について配布用権限を取得できる |
| P0 | App Store審査方針 | 広告視聴をScreen Time制限の解除条件にする方式が審査可能か確認できる |
| P1 | 複数ルールの重複 | 一方の終了時に別ルールのロックを誤解除しない |
| P1 | 端末再起動と時刻変更 | ルール、回数、一時解除期限が破綻しない |

### 重要な技術・審査上の注意

- AppleのScreen Time関連フレームワーク（Family Controls、Managed Settings、Device Activity）を利用する想定である。
- Shieldのボタン操作は`ShieldActionDelegate`で処理できるが、**ロック中に対象アプリを押すたびに、ボタン操作なしで正確に通知されることは公開仕様から保証できない**。このため押下回数の検証を最初に行う。
- 広告はShield内で再生せず、本アプリへ移動して表示する。
- AppleのApp Review Guidelines 4.10は、Screen Time APIなどOS組み込み機能の収益化を禁止している。広告視聴による解除が該当すると判断される可能性があるため、**広告方式はApp Store公開上のリリースブロッカー**として扱う。
- 広告方式が認められない場合の代替案は「30秒待つと5分間解除」とし、ロック・回数記録の中核要件は変更しない。

## 12. 開発の実施順序

1. 1つの対象アプリを手動でロックする実機試作
2. 対象アプリ押下を正確に数えられるか検証
3. Shieldから本アプリへの遷移を検証
4. 5分間解除と自動再ロックを検証
5. Family Controls entitlementと広告方式の審査方針を確認
6. ルール作成・編集・削除を実装
7. 今日の回数表示を実装
8. リワード広告を実装
9. 重複ルール、再起動、日付変更を実機テスト

P0検証のいずれかが不成立の場合は、全画面の作り込みへ進む前に要件を見直す。
